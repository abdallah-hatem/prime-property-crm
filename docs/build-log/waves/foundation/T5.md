## Endpoints

`src/domains/users/` and `src/domains/roles/`. `UsersModule` imports `RolesModule`, so `app.module.ts`
registers only `UsersModule`. Creates answer 201, everything else 200.

- `GET /users` (`users.manage`): `q` (name, email or phone; a phone typed any way also matches its
  E.164), `roleId`, `active`, `page`, `limit` ≤ 20. Sorted by name.
- `GET /users/options` (`owners.assign` or `users.manage`, picker, `limit` ≤ 100): `UserSummary[]`,
  active users unless `active=false`.
- `POST /users`: email trimmed and lower-cased, `409 EMAIL_TAKEN` (pre-check in the transaction, and
  a unique violation from a concurrent create maps to the same code); unknown `roleId` → `400
  INVALID_ROLE`; phone as typed → E.164; scrypt hash via `password.util`.
- `GET /users/:id`: `User & { counts: { owners, listings, openReminders } }` (live owners and
  listings assigned to them, their reminders not done).
- `PATCH /users/:id`: only fields that differ are written; nothing changed = no write, no log entry.
  A role change runs the last-admin check. `active` and `password` → 400 (their own endpoints).
- `POST /users/:id/reset-password`: hash + `SessionService.revokeAllSessions(tx, id)` + activity in
  one transaction; returns `null`.
- `GET /roles/permissions` (`roles.manage`), `GET /roles` (`roles.manage` or `users.manage`, picker:
  built-in first, then by name), `POST /roles` (`409 ROLE_NAME_TAKEN`, case-insensitive; keys deduped
  and stored in the fixed list's order), `PATCH /roles/:id` (`400 BUILT_IN_ROLE` for a change to
  Admin's permissions; both built-in roles can be renamed), `DELETE /roles/:id` (`400 BUILT_IN_ROLE`,
  `409 ROLE_IN_USE` with `data.userCount`; the role row is locked while counting).
- Activity: `USER_CREATE`, `USER_UPDATE` (`details.changed`, and `role.from/to` on a role change),
  `PASSWORD_RESET` (`details.sessionsEnded`), `ROLE_CREATE`, `ROLE_UPDATE` (`name.from/to`,
  `permissions.added/removed`), `ROLE_DELETE`; targets `{ kind: 'USER' | 'ROLE', id, label }`.

## Edge cases → tests

Each plan case is an `it` with its exact name in `test/users-roles.e2e-spec.ts`; the role and user
rules also have unit tests (`users.service.spec.ts`, `roles.service.spec.ts`, `last-admin.service.spec.ts`,
`*.pure.spec.ts`).

- Member without users.manage calls any /users endpoint → 403
- Create user with an existing email (different case) → 409 EMAIL_TAKEN
- Moving the last active admin to another role → 409 LAST_ADMIN (also self-demotion; allowed once a
  second admin exists)
- Two admins demote each other concurrently → at least one admin remains (3 rounds, real parallel
  requests: one 200, one 409, exactly one admin left; also green on the one-connection pool)
- Editing Admin role's permissions → 400 BUILT_IN_ROLE; renaming Team member allowed
- Delete a built-in role → 400; delete a role with users → 409 ROLE_IN_USE (a deactivated holder counts)
- Create role with an unknown permission key → 400
- Permission change reflected in the next access token (refresh carries the new key; `/auth/me` is live)
- Every user/role change writes an activity entry (exact sequence of six; no-op PATCH and refused
  delete write none)
- Member calls /roles and /roles/permissions → 403
- Generic: no token / expired / forged → 401 on every route; validation 400s (missing, empty, too
  long, wrong type, extra field, `null`, malformed UUID id); unknown id → 404; pagination (page 0,
  −1, 1.5, limit 0/21/abc, picker limit 101, page past the end empty, limit 1 sets `hasNextPage`);
  search with `%`, `_`, `'` and `"` matched literally; Arabic names and search; phone `01001234567`,
  `+20 100 123 4567`, `0020-…`, `(010) …` all stored `+201001234567`; 10 or 12 digits, `013…`,
  text → 400.

## Decisions and deviations

- **`Role.builtIn` is `'ADMIN' | 'TEAM_MEMBER' | null`**, not a boolean (the spec's shape doesn't
  say). It is still truthy for built-ins; the web can tell Admin (permissions locked) from Team member.
- **Sending Admin's full permission list back is accepted** (no-op), so a role form can post every
  field; any other list for Admin is 400 `BUILT_IN_ROLE`.
- **Added `400 INVALID_ROLE`** for a `roleId` that names no role (not in the contract table).
- **Last-admin lock is a row lock on the Admin role**, not a serializable transaction: no retry
  loop needed, and creating or promoting users isn't blocked (their FK check takes `KEY SHARE`).
- Role names are unique ignoring case at the service (the DB index is case-sensitive; two
  differently-cased creates racing could both pass — acceptable).
- `UpdateUserDto` / `UpdateRoleDto` are written out, not `PartialType`: `@nestjs/mapped-types`
  isn't a dependency and adding one would touch the shared lockfile; the contract specs pin them.
- `docs/BUSINESS_LOGIC.md`: added the "Users and roles (built, T5)" paragraph.
- No schema change.
