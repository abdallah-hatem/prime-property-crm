## Screens

- `/analytics` (analytics.view): range pills — Today, Yesterday, This week (Egyptian week, from
  Saturday), Last 7 days, This month, Last 30 days — and Custom (shared `Calendar` in a popover,
  two taps, ≤ 366 days, nothing after today). The URL holds `range=<preset>` (relative, so a saved
  link keeps meaning "last 7 days") or `from`/`to`; the page resolves either into Cairo dates
  (`resolveRange`: one date = that day, reversed swapped, longer than 366 cut to 366 ending at `to`,
  junk → today). Range changes go through `useUrlParams` (`scroll: false`), the content dims while
  the next range renders. Team totals as eight tiles (calls, interested owners, reminders done,
  reminders overdue — red when > 0, assigned owners, listings created, ads live, ads taken down; the
  three counted at the range end say so), the outcomes breakdown chart, and the member table.
- Outcomes chart: one horizontal bar per outcome, longest first, growing from the start edge (right
  in Arabic), each labelled with its count and share; single series, so no legend; `chart-1` (checked
  with the dataviz validator against the light and dark card surfaces: all checks pass).
- Member table: shared `DataList` (cards on phones with calls / interested / overdue, table from md,
  more columns from lg), sortable by any stat or the name (select + direction toggle, ties by name),
  deactivated members carry a "Deactivated" chip. A row / card opens the member for the same range.
- `/analytics/members/[id]`: back to the team (same range), name, deactivated note, the same range
  pills, the eight tiles, **calls by day** (column chart: a column per Cairo day, per week from
  Saturday past 62 days; time runs from the start edge, so right-to-left in Arabic; y-axis 0 / half /
  a clean top; hover, tap or arrow keys show the day and count; a screen-reader table holds every
  value) and the member's outcomes. Unknown member → 404 page.
- Empty range state: nothing counted inside the range (calls, reminders done, interested owners,
  listings created, ads taken down all 0) → "Nothing happened in this range" in place of the charts,
  with "Show the last 30 days" (not offered when the range already is that). The end-of-range tiles
  stay.
- Skeletons in shape: `loading.tsx` for both routes (`AnalyticsSkeleton`, `MemberAnalyticsSkeleton`:
  header, pills, tiles, chart card, member rows).
- **Export to Excel** (`ExportButton`, data.export only — absent otherwise): on the admin owners
  table (labelled, under the header) and in the listings search row (icon on phones, label from sm).
  Sends the list's current URL filters minus `page`/`limit`; spinner + "Preparing file…" and disabled
  while the file is prepared (one request however often it's tapped); the file saves as the API's
  `owners-YYYY-MM-DD.xlsx`; EXPORT_TOO_LARGE and other refusals toast through `handleResponse`
  (`error.EXPORT_TOO_LARGE`).

## Decisions and deviations

- **Week starts on Saturday** (Egyptian calendar; the spec doesn't say). The calendar keeps its
  locale's week (Monday in English) — shared component, untouched.
- **Presets live in the URL by name**, custom ranges as dates; members open with the same range.
- **"Empty" = nothing counted inside the range**; end-of-range counts can still be non-zero and stay.
- Charts are hand-built HTML (no chart library dependency); one series each, `chart-1`.
- Over 62 days the calls chart sums by week (from Saturday) so columns stay readable on a phone.
- `homeFor` (src/lib/routes.ts) says "the admin dashboard (T17) changes only this function": not
  changed — `src/lib` is shared and the brief didn't ask for an admin home.

## Shared changes wanted (not made, per brief)

- `src/lib/api.ts`: a raw/binary response mode (e.g. `responseType: 'arrayBuffer'`) so exports can
  use `apiFetch` (refresh-and-retry on 401 included) instead of `export-actions.ts`.
- `ui/calendar.tsx`: the RTL month arrows; an optional `weekStartsOn` (Saturday for this team).
- `filter-chips.tsx`: allow a trailing element (the Custom pill) inside its row instead of the
  wrapper/override used here.
- `vitest.setup.ts`: the jsdom polyfills (ResizeObserver, pointer capture, scrollIntoView) repeated
  at the top of the test file.

## Contract gaps

- Analytics outcome labels follow the **account's saved language**, not the request's
  `Accept-Language` (the contract says "the caller's language"); the pages relabel them from
  `GET /call-outcomes` (hidden outcomes keep the API's label).
- No shared zod schema for the export query (`OwnerListQuery`/`ListingListQuery` minus paging).
- `EXPORT_TOO_LARGE` carries no count; the message says "over 50,000".
