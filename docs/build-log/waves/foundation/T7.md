## Endpoints

- `POST /owners/:id/calls` (201): the owner must be live and assigned to the caller. Anyone else's,
  unassigned or trashed owner is a 404, the admin included. `409 DO_NOT_CALL` / `409 OWNER_LISTED`.
  The phone (typed any way) must be one of the owner's numbers: `400 PHONE_NOT_OWNERS`. Idempotent
  per member by `clientRequestId`: a repeat returns the same call, and two taps at once also return
  one call (the unique index loser re-reads). The same id on another owner gets `409 REQUEST_ID_REUSED`.
  Stores `ownerName` and the E.164 phone, and moves `Owner.lastCallAt` forward (never back).
- `POST /calls/:id/outcome` (200): only the call's member (404 otherwise). `409 OUTCOME_ALREADY_SET`
  is checked first, then again by a conditional update, so two at once give 200 + 409. An unknown
  outcome is a 404; a hidden one is `400 OUTCOME_HIDDEN`. The status follows the mapping unless a
  call that started later already has an outcome, or the owner is LISTED or DO_NOT_CALL. The
  optional `reminder` is a MANUAL reminder on the owner for the owner's current member. In the
  past, it is `400 REMINDER_IN_PAST` and the whole transaction rolls back. On a trashed owner's
  call, the outcome saves without a status change, and with a reminder the answer is 404.
- `GET /calls`: `memberId, ownerId, outcomeId, from, to` (Cairo date or ISO instant, on `startedAt`),
  `missingOutcome`. Without `analytics.view`, `memberId` is forced to the caller. Newest first.
- `GET /call-outcomes` (any; a *picker*, limit ≤ 100, default 100; `includeHidden` needs
  `settings.manage`, else 403). Ordered by `order`, then label. `POST` / `PATCH` / `DELETE`
  need `settings.manage`. LISTED → 400 at the DTO; `order` is 0–10 000; labels are trimmed,
  1–100 chars. Create appends (`max(order)+1`). Each create, effective edit and delete writes one
  `OUTCOME_UPDATE` (target `CALL_OUTCOME`, `details.changed` with from/to); a no-op PATCH writes
  nothing. DELETE deletes only when no call uses it (one statement), else `409 OUTCOME_IN_USE`.
- `/reminders`: `GET` adds `state`, `when` (`overdue` = open and due < now; `today` = now ≤ due <
  end of the Cairo day; `upcoming` = due ≥ end of today), `kind` and `memberId` (403 without
  `analytics.view` unless it is the caller). `unassigned` with `memberId` → 400. Order: open first
  by `dueAt`, so overdue leads; done ones follow, newest done first. Reminders on trashed records
  are hidden and answer 404. `POST` (201, MANUAL) needs exactly one live `ownerId`/`listingId`
  assigned to the caller (404 otherwise, unassigned included) and a future `dueAt` (ISO with a zone).
  `PATCH` (its member) takes `{ dueAt?, note? | null }`: `409 REMINDER_DONE`, `400 SYSTEM_REMINDER`
  for an AD_TAKE_DOWN's `dueAt` (its note and an AD_CHECK_IN's due time can change), and
  `400 REMINDER_IN_PAST`. `POST :id/done` (200): `400 SYSTEM_REMINDER` for both ad kinds; done
  again is a no-op returning the first `doneAt`.
- `GET /me/today`: `outcomeMissing` (own calls without an outcome, any date, newest first),
  `overdue` / `dueToday` (MANUAL only), `adTasks` (every open AD_TAKE_DOWN plus AD_CHECK_IN due
  before the end of today), each ≤ 50, and `counts { callsToday (Cairo day), remindersOpen (all
  kinds, live records) }`.
- `AllExceptionsFilter`: errors in the `http-errors` shape (a 4xx `status` and `expose: true`,
  e.g. body-parser's too-large and malformed-JSON errors) become the envelope with that status:
  413 → `PAYLOAD_TOO_LARGE`, "The request body is too large". Covered by a unit test and an e2e test
  (a body over 1 MB).

## Decisions and deviations

- **A call outcome never changes a DO_NOT_CALL owner** (as with LISTED): the business doc says only
  the admin clears Do not call. Added to `BUSINESS_LOGIC.md`.
- **The plan says nothing on the admin calling**: `POST /owners/:id/calls` is "own owner only", so
  the admin gets 404 on owners not assigned to them. Same for reminder writes ("its member").
- **New error codes** the contract table doesn't list: `400 PHONE_NOT_OWNERS` (the plan's "→ 400"),
  `409 REQUEST_ID_REUSED`, and a 404 for an unknown `outcomeId`.
- **`GET /call-outcomes` is a picker** (limit ≤ 100, default 100) so the outcome sheet gets the
  whole list in one page. The contract didn't mark it.
- **Done twice is a no-op, not 409**: the contract lists no error for `done`. A double tap must not
  fail.
- **`GET /reminders` order** is "open first by dueAt, then done newest first", not plain `dueAt`.
  With `state` unset, plain `dueAt` would put old done reminders above overdue ones.
- **`/me/today` lists** split by kind: `overdue`/`dueToday` hold MANUAL reminders only; ad reminders
  live in `adTasks`. `outcomeMissing` is any date (the business doc: "until one is set").
- **The DTO for a reminder's due time requires a zone** (`Z` or `±hh:mm`), matching zod
  `iso.datetime({ offset: true })`.
- **Owner writes from the calls repository**: `CallRepository` updates `owners.last_call_at` and
  `owners.status` itself (lint forbids importing OwnerRepository, and OwnersService has no such
  method). Kept to the two columns.
- No schema change was needed.
- `docs/BUSINESS_LOGIC.md`: new paragraph "Calls, outcomes and reminders (built, T7)".
