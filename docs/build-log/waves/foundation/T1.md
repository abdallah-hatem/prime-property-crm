## Schema (`apps/api/prisma/schema.prisma`)

Models: `Role`, `User`, `RefreshToken`, `Owner`, `OwnerPhone`, `OwnerAssignment`, `Call`,
`CallOutcome`, `Reminder`, `Note`, `Listing`, `Photo`, `ImportJob`, `ImportRow`, `ActivityEntry`,
`Setting`. Enums mirror the shared contract (plus `BuiltInRole`, `ImportKind`, `ImportStatus`,
`ImportIssueReason`); `src/database/schema-enums.spec.ts` fails if they drift.

- UUID keys, snake_case via `@map`, `createdAt`/`updatedAt`, an index on every FK and filtered
  column (owner `assignedTo+status+lastCallAt`, listing search columns, reminder
  `member+doneAt+dueAt`, `deletedAt` on soft-deleted tables, activity `type/actor+createdAt`).
- `Call.owner` → `SET NULL` (with `ownerName` snapshot); `Call.member`, `Call.outcome`,
  `ActivityEntry.actor` → `RESTRICT`. Phones, notes, reminders, photos, import rows cascade
  from their parent (they go with it on purge). FKs to users are `RESTRICT` (users are
  deactivated, never deleted).
- `OwnerPhone.phone` is globally unique (E.164), trashed owners included; max 3 slots (0..2).
- `Listing.ownerId` and `Listing.ownerPhone` are unique **among live listings** (partial unique
  indexes via the `partialIndexes` preview feature, so the schema and the SQL stay in sync).
- `Call @@unique([memberId, clientRequestId])` for the idempotent call start.
- `RefreshToken`: `tokenHash` unique, `familyId`, `usedAt`, `revokedAt`, `replacedById`, `expiresAt`.
- `Setting` is a singleton (`id = 1`).

Hand-written CHECKs at the end of the init migration: reminder and note owner xor listing;
price 1..1,000,000,000; `size_sqm > 0`; bedrooms/bathrooms ≥ 0; outcome `sets_status <> 'LISTED'`;
call `outcome_id` and `outcome_at` set together; phone position 0..2; settings `id = 1` and
interval 1..90.

## API pieces

- `prisma/seed-foundation.ts` (`seedFoundation(db, admin)`) and `prisma/seed.ts` (entrypoint,
  `tsx`, wired as the Prisma 7 seed in `prisma.config.ts`; scripts `db:migrate`, `db:deploy`,
  `db:seed`). Env: `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, optional `SEED_ADMIN_NAME`
  (placeholders in `.env.example`). Idempotent: Admin's permissions reset to the full list;
  Team member left as edited; default outcomes created only while the table is empty (an admin's
  renames and deletions are never undone); settings and admin created only if missing (a re-seed
  never resets the admin's password).

Every T1 case in the plan has an `it` with its name. Extra: owner purge nulls the call link and

## Decisions and deviations from the plan

- **`Listing.ownerId` is not a plain unique** (the plan said "nullable unique"): a trashed listing
  keeps its `ownerId` for restore, and the business doc allows a new listing for that owner
  meanwhile ("restore refused if the owner has another listing by then"). Partial unique on live
  rows instead; same for `ownerPhone` (backs `409 PHONE_IN_LISTING`).
- **A fractional price is truncated silently** by Prisma 7 + adapter-pg (`1500.5` → `1500`), not
  rejected. The DB can't see it; the listing DTO (T8) must use `@IsInt()`. The test documents this.
- **Added `OwnerAssignment`** (not in the plan's list): the owner timeline needs per-owner
  `ASSIGN { from, to, by, at }` items, which the per-batch activity entry can't give.
- **Added `Owner.lastCallAt`** (calling-list sort) and **`Listing.adTakenDownAt`** (analytics
  `adsTakenDown` in a range). T7/T8 maintain them.
- **Role identity is `builtIn` (`ADMIN`/`TEAM_MEMBER`, unique)**, not the name, so the Team member
  role can be renamed (T5) and the seed still finds it.
- **No DB trigger blocking UPDATE/DELETE on calls/activity**: it would block e2e teardown and the
  purge cron's `SET NULL`; immutability is enforced by the repository layer and the FK rules.
- Prisma 7's `migrate dev` does not regenerate the client: run `npm run prisma:generate -w
  @prime-crm/api` (or `npm install`) after pulling a schema change.
