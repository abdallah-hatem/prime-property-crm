## Auth routing (`src/proxy.ts` → `src/lib/auth-proxy.ts`)

Next 16 renamed `middleware` to `proxy`; same place in the request, Node runtime.

- Access JWT (15 min) and refresh token (30 days) live in httpOnly cookies `prime_at` / `prime_rt`
  (`sameSite=lax`, `secure` in production), set only by the proxy, server actions and the sign-out
  route. Claims are decoded (not verified) for routing only; the API verifies every call.
- Access expired or within 60 s of expiry + refresh cookie → `POST /auth/refresh` in the proxy; the
  new access token is written into this request's Cookie header (the render sees it) and both
  cookies are set on its response. No redirect. Same-token refreshes on one instance share one API
  call (`refreshSession`, settled result kept 5 s); other instances rely on the API's 30 s grace.
- Refresh refused (400/401) → cookies cleared → signed out → `/login?next=…`. API unreachable →
  cookies kept, no sign-out.
- `homeFor(permissions)` in `src/lib/routes.ts` is the one home decision (everyone → `/today`).
  `ADMIN_ROUTES` maps each admin page to its permission; the proxy, sidebar, tab bar and More page
  all read it. Server actions (`next-action`) are refreshed but never redirected.
- `apiFetch` on 401: in a server action refresh inline + retry once (or clear cookies → `unauthorized`);
  in a render redirect to `/api/auth/signout?next=` (clears cookies, avoids a login ↔ page loop).

## Decisions and deviations

- **`proxy.ts`, not `middleware.ts`** (Next 16 rename; the plan says middleware).
- **`apiFetch` is `server-only`, not `"use server"`**: a generic fetcher exported as a server
  action would let a browser call any API path with the user's cookie. Endpoints stay in `src/apis.ts`.
- **Login does a full page load** after success so the root layout renders the new session from
  the first paint; the button stays locked until then.
- **Language switch also saves `language` on the account** (`PATCH /auth/me`); first sign-in on a
  device sets the locale cookie from the account. The preferences spec uses the Team lead account
  and switches it back.
- **Tablet (≥ md, 768 px) gets the sidebar**; phones get the tab bar and a slim top bar with the
  account button. Inactive tabs are icon-only (labelled for screen readers), as in the mockup.
- Status colours: lead NEW/LISTED primary, INTERESTED success, CALL_BACK warning, others neutral;
  listing AVAILABLE success; ad LIVE success with the live ripple. Red is never a status.
- `vitest.setup.ts` skips DOM setup for `// @vitest-environment node` files.
- Sign-out lives in the account menu and on the More page (same `AccountPanel`).
