## Endpoints

`GET /owners` · `GET /owners/calling-list` · `GET /owners/ids` · `POST /owners` · `GET/PATCH/DELETE
/owners/:id` · `POST /owners/assign` · `GET /owners/:id/timeline` · `GET/POST /owners/:id/notes` ·
`GET /lookups/areas` · `GET /reminders` (only `unassigned=true` plus the caller's own list).

- Scoping: without `owners.viewAll` every list is the caller's own owners whatever `assignedTo` /
  `importId` say; a not-yours, unassigned, deleted or unknown id is one 404.
- Search `q`: name (wildcards escaped with `escapeLike`) or phone digits (separators, a leading
  `0`, `+20`, `0020` and Arabic-Indic digits handled), so `0100 123`, `+20100123` both match.
- Calling list: one SQL ORDER BY — overdue (open, due before now) → due later today (end of the
  Cairo day from `cairoToday`) → NEW, CALL_BACK, CONTACTED, INTERESTED, NOT_INTERESTED;
  `last_call_at NULLS FIRST`, then `created_at`, then id. LISTED / DO_NOT_CALL excluded.
- `OwnerRow.lastCall` = latest call **with an outcome**; labels in the caller's stored language.
  `nextReminderAt` = earliest open reminder on the owner.
- Create/PATCH phones: normalised; conflicts checked inside the transaction against owner phones
  (trashed included) and live listings' owner phones; a lost race on the unique index maps to the
  same 409. `PHONE_EXISTS` carries `{ phone, ownerId | listingId }` only for `owners.viewAll`;
  `PHONE_IN_TRASH` (with the trashed `ownerId`) only for `trash.restore`. PATCH `phones` replaces
  the list; the owner's own phones and its linked listing's phone are not conflicts.
- Delete (`owners.import`): `409 OWNER_LISTED` with a live listing; else closes open reminders
  (`doneAt = now`) and `TrashService.softDelete` (logs DELETE). Calls untouched.
- Assign: assignee must be active (`400 INVALID_ASSIGNEE`); ids deduped, deleted/unknown skipped,
  `moved` = live owners in the batch; one `ASSIGN` activity entry per batch (`details: { kind:
  'OWNERS', count, assigneeId }`), none when nothing moved. `POST /owners` with `assignedTo`
  goes through the same helper (needs `owners.assign`, else 403).
- Timeline: UNION over calls / notes / reminders / owner_assignments, newest first, paginated;
  each item also carries `at` (additive to the contract).

## Decisions and deviations

- **`/owners/ids` reaches every owner for `owners.assign` holders** (the plan doesn't say): a team
  lead without `owners.viewAll` must be able to pick "next 200 unassigned". Without `viewAll` the
  phone part of `q` is dropped there, so ids can't be used to probe phones.
- **Do not call on a Listed owner → `409 OWNER_LISTED`**; clearing it when not set is a no-op.
- **Closing a reminder = `doneAt = now`** (no schema change). T11: a reminder closed by a delete
  counts as "done" unless analytics excludes reminders of deleted owners/listings.
- **Express body limit raised to 1 MB**: 5000 UUIDs (~200 KB) got a 500 from body-parser. A
  body-parser 413 still reaches the client as 500 (the filter only maps HttpExceptions) — worth a
  small fix in `AllExceptionsFilter`.
- `GET /lookups/areas` is paginated (picker, `limit` ≤ 100); `q` matches an area or a compound.
- Helper signatures take id lists (`{ ownerIds?, listingIds? }`) rather than a single
  `{ ownerId | listingId }`, so bulk assign and hand-over are one query each.
- Phone DTO validators live in `domains/owners/dto/owner-validators.ts` (`IsPhoneInput`,
  `DistinctPhones`, `IsOptionalNotNull`) to stay clear of T5's `common/validators/is-phone.validator.ts`;
  unify at merge.
- `docs/BUSINESS_LOGIC.md`: calling-list detail, Do not call on Listed, assign batch rules,
  restored owner.
