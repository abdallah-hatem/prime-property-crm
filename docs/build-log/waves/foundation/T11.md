## Endpoints

- `GET /analytics/team`, `GET /analytics/members/:id` (`analytics.view`). `from`/`to` are Cairo
  dates (`YYYY-MM-DD`), both included; none = today, one = that day; `from > to` or > 366 days →
  `400 INVALID_RANGE`; Feb 30 → `400 VALIDATION_FAILED`. Team: `{ range, totals, members[] }`,
  member: `UserSummary & Stats & { active, range, byDay }` (`byDay` has every day of the range).
  Unknown member → 404. Nine SQL `GROUP BY` queries per request whatever the team size
  (`AnalyticsRepository`), plus the user list and outcome labels.
- `GET /exports/owners`, `GET /exports/listings` (`data.export`): the list endpoints' filters
  (no `page`/`limit`), `.xlsx` via `@RawResponse()` + `StreamableFile`
  (`attachment; filename="owners-YYYY-MM-DD.xlsx"`, Cairo date). Counts first: > 50 000 →
  `400 EXPORT_TOO_LARGE` without reading rows. Phone columns are string cells with format `@`.
  Headers/labels in the caller's language; Arabic sheets are right-to-left. One `EXPORT` activity
  entry (`details: { kind, count, filters }`), none when refused.
- `GET|POST /api/internal/cron/purge`, `GET|POST /api/internal/cron/ad-check-ins`: `@Public()` +
  `CronSecretGuard` (`Authorization: Bearer <CRON_SECRET>`, constant-time compare). Unset secret →
  `401 CRON_NOT_CONFIGURED` for everyone; wrong/missing → `401 UNAUTHORIZED`. Answer
  `{ photos, listings, owners, refreshTokens, loginAttempts }` / `{ added, duplicatesRemoved }`.

## Decisions and deviations

- **"At the range end" means `min(end, now)`.** A range ending later today would otherwise count
  every reminder due later today as overdue. Past ranges are counted exactly at their end.
- **assignedOwners at a past moment follows `owner_assignments`** (latest change before it, else the
  `from` of the first change after it, else today's member). Listings have no assignment history,
  so adsLive/adsTakenDown use the listing's current member; adsLive at a past moment is "posted
  before it and Live now or taken down after it".
- **interestedOwners** = distinct owners whose call *started* in the range got an outcome that
  sets INTERESTED (a purged owner counts per call). **listingsCreated** counts by creator.
- **Members listed**: every active user plus any user (deactivated) with a non-zero stat in the
  range; members carry `active` (additive to the contract's `UserSummary & Stats`). Team totals are
  the sum of the listed members, so unassigned work is not in them.
- **remindersDone includes ad check-ins/take-downs** closed by the ad lifecycle (check-in recorded,
  ad Taken down, and a check-in closed because the listing left Available). Only delete closures are
  flagged. If the web wants "manual reminders done" only, filter by kind later.
- **Exports respect visibility** (the contract only says "data.export"): without `owners.viewAll`
  the owners export is the caller's own owners (same as `GET /owners`); the listings export blanks
  owner name and phone where the caller couldn't see the phone.
- **Purge**: a trashed listing is removed only after all its photos (and their Blob files) are
  gone, so a cascade never orphans a file. A Blob failure is logged and leaves those photos (and
  their listings) for the next night; the rest of the purge still runs. Without
  `BLOB_READ_WRITE_TOKEN` no file can exist, so rows go without a Blob call. No activity entry for
  purges (`actorId` is required; the job has no user).
- **Ad safety net** due date: one interval (setting now) after the last check-in, else after going
  Live, but never in the past. Duplicate open check-ins: all but the earliest due are deleted.
  Batches of 200 under an advisory lock; listings locked by another transaction are skipped till the
  next run.
- Crons answer the envelope (JSON) with counts; GET for Vercel, POST for manual runs.
- New dependency `exceljs` (^4.4.0) in `apps/api` (T9 was told to use the same).
