## Decisions and deviations

- **Upload handshake is a server action, not `upload()` + route handler**: the browser can't hold
  the bearer, and `upload()` swallows the handshake's status and error code, so
  UPLOADS_NOT_CONFIGURED could not be told apart. `REQUEST_LISTING_PHOTO_TOKEN` posts the same
  handshake body to `POST /uploads/listing-photo` and the browser `put`s with the client token
  (what `upload()` does internally). It reads the raw answer with `fetch` (eslint-disable with a
  reason): `apiFetch` only returns enveloped data. Store access assumed `public`.
- Listing / photo error codes are translated under `listings.error.*` (the brief allowed only the
  `listings` namespace); `listingErrorMessage` falls back to the shared `error.*`.
- Take-down task "open" is derived (ad Live on a non-Available listing): `Listing` carries no
  reminders.
- Owner avatar on the detail uses primary-soft, not the mockup's amber (DESIGN: amber only when
  waiting on the user).
- Assigning a member on create (`assignedTo`) is not in the form (needs a member picker).
- Locally, Turbopack (`next dev` / `next build` default) could not fetch Google Fonts on this
  machine (timeouts in its Rust fetcher; Node fetch works), so servers ran with `--webpack`.
