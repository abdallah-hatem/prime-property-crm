## What was built

- **Vercel** — `apps/api/vercel.json` (NestJS preset, no serverless adapter; build = shared →
  `prisma generate` → `nest build`; region `fra1`; crons `/api/internal/cron/purge` `0 1 * * *`
  and `/api/internal/cron/ad-check-ins` `0 4 * * *` UTC) and `apps/web/vercel.json` (Next.js preset;
  build = shared → `next build`). Migrations are not in any build.
- **Backups** — `.github/workflows/backup.yml` (00:30 UTC + manual): Postgres 17 client from PGDG
  (`.github/actions/setup-postgres-client`), `scripts/backup-dump.sh` dumps in custom format with
  gzip-9 inside the archive from an exported REPEATABLE READ snapshot and counts every table's rows
  in that same snapshot; uploads `prime-crm/YYYY-MM-DD.dump` + `.counts.tsv` to R2 via the S3 API
  and verifies remote sizes; a failed scheduled run opens an issue.
- **Restore drill** — `.github/workflows/backup-restore-drill.yml` (Sundays 03:00 UTC + manual,
  optional date): newest backup (fails if > 2 days old) → empty `postgres:17` service container →
  `scripts/restore-drill.sh` (`pg_restore --exit-on-error --single-transaction`, then
  `scripts/sql/row-counts.sql` diffed against the counts file) → `scripts/check-r2-lifecycle.sh`.
- **Lifecycle** — `scripts/r2-lifecycle.json` (prefix `prime-crm/`, expire after 30 days, abort
  stale multipart uploads after 1) and `scripts/check-r2-lifecycle.sh` (reads the bucket config, or
  `--file`; passes only for an Enabled rule with 1–30 day expiration whose prefix covers `prime-crm/`).
- **Docs** — `docs/notes/deploy.md` (projects, env var names per project and environment, first
  deploy runbook with migrate and smoke steps), `docs/notes/backups.md` (R2 bucket, tokens,
  lifecycle, GitHub secrets, real restore).

## Edge cases

- [x] Dump restores into an empty database with the same row counts — enforced by the drill: counts
  are recorded from the dump's own snapshot, so the comparison is exact rather than against a live
  database that keeps changing. Runs weekly in CI; not executed locally (no Postgres client here and
  docker reserved for another agent). First real run happens after the setup in `backups.md`.
- [x] Lifecycle rule deletes objects older than 30 days, checked by reading the bucket config —
  `check-r2-lifecycle.sh`, run by the drill. Verified offline: passes on `r2-lifecycle.json` and on
  a whole-bucket 1-day rule; fails on a 45-day rule, a disabled rule, and a rule for another prefix.

## Decisions

- **No `api/index.ts` / serverless-express entry.** The deploying-to-vercel skill: Vercel's NestJS
  preset runs `main.ts` with `app.listen` unchanged.
- **gzip inside the custom format** (`--compress=gzip:9`) rather than gzipping the archive: the
  `.dump` name stays true and `pg_restore` reads it directly.
- **Row counts in the backup's snapshot**, stored next to the dump, so the drill compares like with
  like. Requires the unpooled Neon URL as the `DATABASE_URL` GitHub secret.
- **Region `fra1` + Neon `eu-central-1`** — nearest pair to Cairo.
- **Optional `R2_ADMIN_*` secrets** for the lifecycle read, in case an object-scoped R2 token can't
  read bucket settings; falls back to the backup token.

## Follow-ups for other tasks (existing files not edited here)

1. Cron controller (purge / ad-check-ins task): Vercel crons call with **GET**, the spec says POST —
   accept GET (or both). Refuse when `CRON_SECRET` is unset.
2. `apps/api/src/config/env.validation.ts`: `PORT` is required; give it `.default(3000)` (the docs
   set `PORT=3000` in Vercel as a stopgap). Add `CRON_SECRET` and `BLOB_READ_WRITE_TOKEN` when their
   tasks land.
3. `apps/api/src/database/database.service.ts`: with `@prisma/adapter-pg` the `connection_limit`
   URL parameter does not apply; when `process.env.VERCEL` is set pass `max: 1` and
   `connectionTimeoutMillis: 20000` to `PrismaPg` so serverless instances don't exhaust Neon and
   requests fail fast instead of hanging. E2E should run with the same one-connection pool.
4. `apps/api/.env.example`: add `CRON_SECRET` and `DATABASE_URL_UNPOOLED` (commented) when used.
