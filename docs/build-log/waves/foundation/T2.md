## Decisions and deviations

- **Agent databases end in `_test`** (`prime_crm_<name>_test`, not `prime_crm_<name>`), so the
  existing e2e guard keeps refusing everything else unchanged and `drop` can never reach a
  non-test database.
- **The template holds the foundation seed only** (with the admin from `apps/api/.env`); sample
  data is opt-in per agent database via `npm run db:seed`. The e2e suite passes either way.
- **Sample gate: `SEED_ALLOW_SAMPLE=true` required, `NODE_ENV=production` refused.** Production
  deploys keep running `db:seed` for the foundation; preview is seeded from a dev machine with the
  flag set.
- **A re-seed restores fixture state** (times relative to now), so "overdue", "due today" and
  "deleted 5 days ago" stay true; a sample password is re-hashed only when it no longer matches.
- **The seed idempotency test uses a scratch database** of its own instead of the shared e2e one,
  so sample rows never leak into other specs.
- Sample phones use reserved blocks (`+20 10/11/12/15 555xxxxx`); photo URLs use placehold.co.
