## Screens

- **Today** (`/today`): counter board (overdue, due today, outcome missing — the lengths of the
  `/me/today` lists), Needs an outcome (amber cards, "Add outcome" opens the sheet), Overdue and
  Due today (reminder rows with Call; the owner's phones are fetched on tap), Ad tasks (link to
  `/listings/:id`, may 404 until T14), Calling list (`GET /owners/calling-list`, "Show more owners"
  appends the next page, rows from a refreshed first page are de-duplicated). Empty state when
  nothing waits and nobody is left to call. "All reminders" in the header.
- **Call flow** (`src/components/calling/call-flow.tsx`, mounted once in `(app)/layout.tsx`):
  tap Call → phone picker if several → `POST /owners/:id/calls` with a `clientRequestId` kept per
  owner + number until the call exists (a retry after a network failure reuses it; a refusal
  drops it) → `tel:` via a link click (`src/lib/tel.ts`) → when the page is hidden/blurred and comes
  back, the outcome sheet opens. If the page never leaves (desktop, no dialer) the sheet opens
  after 3 s. One call at a time: every Call button locks while one is being created.
- **Outcome sheet** (`outcome-sheet.tsx`): outcomes from `GET /call-outcomes` in the reader's
  language (cached per page session), required; note (counter); optional reminder with quick
  picks + calendar + quarter-hour time, Cairo time sent with its offset, past times blocked
  (client, and the API's `REMINDER_IN_PAST` shown under the picker). `OUTCOME_ALREADY_SET` closes
  the sheet; `OUTCOME_HIDDEN` reloads the list. "Later" keeps the call in Outcome missing. Bottom
  sheet on phones, dialog from md.
- **Owners** (`/owners`): search (debounced, URL `q`), status pills (URL `status`), DataList with
  pagination; owners.viewAll users see everyone's with an "Assigned to" column (T15 replaces it).
- **Owner detail** (`/owners/[id]`): name, status, area, member, import source; Call (gradient) and
  each phone row calls that number (only the assigned member, not Listed / Do not call); Create
  listing for INTERESTED (`/listings/new?ownerId=`); Do not call (member on own, admin too) and
  Clear (owners.viewAll) behind a confirm; notes (add, list); reminders (add, edit, done; others'
  read-only); history (calls, notes, reminders, assignments). Two columns from lg.
- **Reminders** (`/reminders`): Open / Overdue / Today / Upcoming / Done (URL `when`), Done and
  Edit on own manual reminders; ad check-in / take-down rows say why they close through the
  listing instead of a Done button.

## Decisions and deviations

- **`GET /reminders` has no `ownerId` filter** (contract gap): owner detail derives its reminders
  from the owner's timeline (up to 5 pages = 100 items).
- **Today lists hold ≤ 50 items**, so a counter shows at most 50 (the lengths, not a count field;
  `counts` has only `callsToday` and `remindersOpen`).
- **Today's reminder rows carry no phones**: Call fetches `GET /owners/:id` first.
- **The admin can't call** owners assigned to others (T7: 404), so Call shows only for the assigned
  member; others see who it is assigned to.
- **Playwright `workers: 1`**: the specs share the seeded accounts and change their data; parallel
  workers raced each other (same first owner called twice).
- **No `/reminders` nav entry**: reached from Today's header ("All reminders").
- `react-day-picker@9` added for the calendar (the house lint bans native date inputs).
- Environment: fonts.googleapis.com / gstatic.com were timing out from this machine, which breaks
  `next build` and Turbopack dev. Local builds used `next build --webpack` with
  `NEXT_FONT_GOOGLE_MOCKED_RESPONSES` pointing at locally downloaded copies (outside the repo).
  Nothing in the repo changed for it.
